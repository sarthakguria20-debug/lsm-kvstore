🏛️ Architecture & The SDE Challenge

How this database engine achieves zero data loss, durability, and crash consistency under sudden hardware power loss.

1. The SDE Challenge: Why Standard I/O Fails

In standard software, calling file.write() or file.flush() only moves bytes from user space into the operating system kernel's page cache. If physical power is cut 50ms later, all buffered data is permanently lost.

Our Solution: Every single mutation executes os.fsync(fd), commanding the physical storage controller to commit bytes to non-volatile flash or platter sectors before returning success.

2. Binary WAL Frame & CRC32 Integrity

If power cuts mid-write, partial bytes reach disk (a torn write). Every record written to disk is framed with a 32-bit CRC32 checksum:

[CRC32: 4B][PAYLOAD_LEN: 4B] [TYPE: 1B][TIMESTAMP_NS: 8B][LSN: 8B][KEY_LEN: 4B][VAL_LEN: 4B][KEY][VAL]

On reboot, recovery validates each frame. If a torn frame is detected, invalid trailing bytes are truncated via os.ftruncate, restoring complete consistency.

3. SkipList Probabilistic MemTable

Unlike self-balancing trees (AVL or Red-Black) which require complex lock rotations during mutations, SkipLists use probabilistic leveling to achieve O(log N) search, insert, and ordered iteration without heavy locking overhead.

4. Kirsch-Mitzenmacher Bloom Filter

Avoids costly disk seeks by computing two 64-bit hashes from SHA-256 and generating k bit positions via: g_i(x) = (h1(x) + i * h2(x)) mod m. Negative queries are rejected in memory with zero disk I/O.

5. Two-Phase Atomic SSTable Flush

When freezing a MemTable, writes go to a temporary file (*.sst.tmp). Only after os.fsync() verifies the data is physically durable does the engine execute os.replace() (an atomic POSIX operation). Interrupted flushes leave clean temporary files pruned on reboot.

6. K-Way Merge Compaction

As writes accumulate, multiple SSTables are created. The compactor uses a min-heap priority queue to stream records from newest to oldest, deduplicating superseded keys and permanently purging tombstones (🪦) to reclaim disk capacity.

🚀 Python API & Quickstart

Easily embed the storage engine directly into your Python backend or distributed service.

from lsm import LSMTree, WriteBatch # Initialize engine with durability guarantees db = LSMTree(data_dir="./data", memtable_max_bytes=4*1024*1024) # 1. Point Mutations (WAL CRC32 + fsync + MemTable SkipList) db.put("user:101", b'{"name": "Alice", "role": "admin"}') value = db.get("user:101") print("Retrieved:", value) # 2. Atomic Transactional Batches (TXN_BEGIN ... TXN_COMMIT) batch = WriteBatch() batch.put("account:A", b"balance:500") batch.put("account:B", b"balance:1200") db.write_batch(batch) # Atomically synced in single fsync # 3. Ordered Range Scan for key, val in db.scan(start_key="account:", end_key="account:\xff"): print(f"{key} -> {val}") # 4. K-Way Compaction (purges superseded records & tombstones) db.compact()
